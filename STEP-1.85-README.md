# HauntLog — Step 1.85: Atlas redesign with map

The Atlas is now a real map-first experience: Leaflet map + draggable bottom
sheet on mobile, 50/50 map+list split on desktop, with search and filters.

## What's new

### Real map
Leaflet + dark CartoDB tiles (no API key, free). Pins by venue type:
- **Red** — catalog (official) venues
- **Grey** — community (user-generated) venues
- **Green** — verified venues (UI-ready; verification flow ships later)

Selected pin glows; tap a pin → list scrolls to that venue and selects it.
Tap a venue in the list → map flies to it.

### Mobile (under 768px wide)
- Map fills the screen
- A drag-handle sheet sits at the bottom with three snap points:
  - **MAP** (12%) — just the handle, map is everything
  - **SPLIT** (40%) — sheet shows ~3 venue cards
  - **LIST** (85%) — list dominates, slim map on top
- Drag the handle freely; releases snap to nearest position. Or tap the
  MAP / SPLIT / LIST chips for instant jumps.
- Top of screen: two pill controls
  - **N LIVE** chip — opens the live check-ins sheet
  - **FILTERS** button — opens search + source + tags as a bottom sheet,
    shows a count badge for active filters

### Desktop (768px+)
- Map left half, list right half
- Filters and search inline above the list
- LIVE NOW chip overlays the map (top-left)
- Click a venue card → map flies to it; click a pin → list highlights it

### Search
- Live filter as you type
- Matches venue name, city, state, tags, and description
- An X clears the search

### Filter pills
- Source: ALL / OFFICIAL / COMMUNITY
- Tags: pipe-separated tags from your CSV, scrollable strip

### Live Now lives in its own sheet
Used to eat ~30% of the page even when empty. Now it's a chip — tap to
open the full list. Disabled appearance when no one is checked in.

### Compact venue rows
Replaces the old card grid. Each row: pin color, name, city/state,
badges, case count, OPEN VENUE link. Tap the row body to select on the
map; tap OPEN VENUE for the detail page.

### Synchronization
Map and list stay in sync through a single `selectedVenueId` state in the
Atlas page. Pin clicks and row clicks both update it. The map flies to
the new selection.

## Layout architecture


## How to apply

1. Stop your dev server (Ctrl+C).
2. Unzip this into your `hauntlog` folder.
3. **Run `npm install`** — Leaflet is a new dependency. This is required.
4. `npm run dev`.
5. Visit `/app/atlas`. On a desktop browser you'll see the map split.
   Drag the browser window narrower than 768px to see the mobile layout.

No localStorage clear needed; data layer didn't change.

## Test loop

### Desktop
1. Open `/app/atlas` in a window wider than 768px.
2. Map shows on the left with ~26 red pins across the US.
3. List shows on the right with all 26 venues, sorted alphabetically.
4. Type "stanley" in search — list filters to just The Stanley Hotel.
5. Click that one row — map flies to Colorado.
6. Clear search. Click a pin in the map — list scrolls to it and
   highlights with a red ring.
7. Click the LIVE NOW chip (top-left of map) — opens the check-ins sheet.
   If no active hunts, says "Nobody is checked in right now."
8. Click a venue card's "OPEN VENUE →" link — goes to its detail page.

### Mobile (resize browser narrow, or use DevTools device mode)
1. Map fills the screen.
2. Bottom sheet at the SPLIT position shows 2-3 cards.
3. Drag the sheet handle up — it snaps to LIST. Map is now a slice
   at the top.
4. Drag down to MAP — only the handle is visible.
5. Or tap the chips (MAP / SPLIT / LIST) for instant jumps.
6. Top: tap FILTERS button. The filter sheet slides up. Type "abandoned"
   in search. Apply. List shrinks; map shows only matching pins.
7. Tap a pin on the map. The map closes nothing — the sheet stays where
   it is — but in the list, that venue is now highlighted with a red ring.
   (At MAP snap, you won't see it; jump to SPLIT.)

## Known limits / things to verify

- **Tiles take a beat on first load.** First time the page opens, the
  map tiles fetch from CartoDB's CDN. Subsequent loads are cached.
- **No GPS auto-zoom.** The map opens on a continental-US view and fits
  to your visible venues. "Zoom to my location" is a future addition.
- **Mobile sheet doesn't fly the map** when you drag it. Map size
  recalculates only after the snap settles (via ResizeObserver). That's
  intentional — keeps the drag smooth.
- **Pin clicks don't open a popup yet.** They select the venue and fly the
  map; the detail is in the list/card. Could add a small popup if you
  want a one-tap path to the venue page without scrolling the list.

## Things to look at and tell me what's off

- Pin sizes — 24px feels right for desktop, might want 28-32 for mobile.
- Snap point fractions (12% / 40% / 85%) — these feel right but only
  testing on your real phone will tell.
- Search behavior — does it feel responsive? Should it search rules
  too, or just name/city/state/tags/description?
- The "OPEN VENUE →" affordance on cards — explicit but adds a row.
  Alternative: tap card to open immediately, double-tap to fly map.
- Filter count badge color — using haunt-red. Could be white. Could
  go in a corner.
